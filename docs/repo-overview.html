Newcomer orientation

A small framework for running game-playing agents against ARC-AGI-3 environments.

The important mental model is simple: main.py chooses an agent and game, Swarm constructs one agent per game, and each Agent repeatedly turns a frame into one GameAction. Random and LLM agents differ almost entirely in how they implement that one decision point.

3. Base Agent Classes

Agent is the main abstraction. It is intentionally opinionated about runtime mechanics and intentionally abstract about game strategy.

The loop

while not is_done(frames, latest_frame) and action_counter <= MAX_ACTIONS:
    action = choose_action(frames, latest_observation)
    frame = take_action(action)
    append_frame(frame)
    action_counter += 1

The subclass does not control how an action is submitted or recorded. It only decides whether the game is done and which GameAction to try next.

Two abstract methods

is_done(frames, latest_frame) decides whether to stop.

choose_action(frames, latest_frame) returns a populated GameAction.

Environment boundary

do_action_request() calls arc_env.step(), passing action data and optional reasoning metadata.

Frame boundary

_convert_raw_frame_data() turns FrameDataRaw arrays into serializable FrameData objects.

Recording

Recorder writes JSONL events when recording is enabled. Playback reads those events and replays saved actions.

Tracing

@trace_agent_session wraps main() so AgentOps can track runs when configured.

Playback is also an Agent

Playback subclasses Agent, raises MAX_ACTIONS, loads a recording, and implements choose_action() by reconstructing each recorded action in order. It overrides append_frame() to avoid double-recording a replay.

4. Random Agent

Random is the clearest example of the contract. It does not manage scorecards, API calls, frame persistence, or threads. It only chooses actions and declares when it is done.

Stop condition

It stops on GameState.WIN. The code includes a commented option to stop on GAME_OVER, but the active behavior allows reset after game over.

Action policy

If the frame is NOT_PLAYED or GAME_OVER, return RESET. Otherwise choose a random non-reset action. Complex actions get random x/y coordinates in the 0..63 range. 

Random extends Agent
  name: include MAX_ACTIONS in recording name
  is_done: stop when latest frame is WIN
  choose_action:
    NOT_PLAYED or GAME_OVER -> RESET
    otherwise -> random action except RESET
    ACTION6-style complex action -> attach x/y data

5. LLM Agent

LLM is more complex because choose_action() becomes a chat protocol. The outward contract is unchanged: after all prompting, message bookkeeping, and parsing, it still returns one GameAction.

At the simple level, LLM serializes the current frame into text, exposes each GameAction as a function/tool, asks the model to choose exactly one action, parses the selected name and arguments, then returns the matching enum.

Force resetAdd initial user prompt, synthesize an assistant function/tool call for RESET, return GameAction.RESET.
ObservationAfter a real action result.
Optional commentaryIf DO_OBSERVATION is true, ask the model for plain-text strategy observations about the latest frame.
Action choiceTool/function call.
Parse and returnUse tool calls for models that require tools, older function calls otherwise. Invalid JSON arguments fall back to an empty dict.
  • FastLLM disables the observation pass to reduce model calls.
  • ReasoningLLM uses tool calls and stores reasoning metadata on action.reasoning.
  • GuidedLLM targets o3, high reasoning effort, and a detailed Locksmith-specific prompt.
  • MyCustomLLM is the intended extension point for custom instructions.

Message state

messages is a rolling conversation window capped by MESSAGE_LIMIT.

Action schema

build_functions() describes reset, simple actions, and coordinate-based complex actions.

Tool mode

MODEL_REQUIRES_TOOLS switches from legacy function-call shape to modern tool-call shape.

Token accounting

track_tokens() accumulates usage and writes token metadata to the recorder.

Prompts

build_user_prompt() gives game context. build_func_resp_prompt() formats state, score, and frame.

Cleanup metadata

cleanup() records prompt and tool schemas before delegating to base cleanup.

Key point: LLM is not a separate runtime. It is a policy implementation inside the same Agent.main() loop, so debugging it usually means inspecting message construction and the final GameAction, not the orchestration path.

6. Registry and Discovery

The CLI can only run agents that appear in AVAILABLE_AGENTS. The registry is built from immediate subclasses of Agent, then augmented with playback recordings and an explicit alias for ReasoningAgent. 

AVAILABLE_AGENTS = {
    cls.__name__.lower(): cls
    for cls in Agent.__subclasses__()
    if cls.__name__ != "Playback"
}

for recording_file in Recorder.list():
    AVAILABLE_AGENTS[recording_file] = Playback
Important nuance: Agent.__subclasses__() only returns direct subclasses. Some classes that inherit from LLM rather than directly from Agent need explicit handling or import side effects to be reachable from the CLI.

7. Deeper Templates

These files are useful after you understand the base contract. They mostly experiment with richer implementations of the same choose_action() idea.

Template What it adds When to read
